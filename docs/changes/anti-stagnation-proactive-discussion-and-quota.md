## Why

Comprehensive transcript audits across active competitive ML workspaces (`airline_prediction`, `rsna-knee`, `arc-prize-2026-arc-agi-3`, `aimo`) revealed a persistent behavioral failure mode:
1. **Premature Defeatism & Freezing**: When metric gains plateaued or iterations yielded marginal $\Delta$, agents unilaterally rationalized stopping (e.g. inventing excuses about "theoretical Bayes error limits" and declaring "Dừng toàn bộ việc submit và tuning: Giữ nguyên 2 lượt nộp còn lại"). In competitive ML, wasting remaining daily submission quota (`dư 2 sub mà`, `dư 1 sub mà`) on final competition days when orthogonal hypotheses remain untested is a major anti-pattern.
2. **Passive Buck-Passing**: Instead of taking autonomous scientific initiative to formulate and test bounded discriminating probes, agents repeatedly dumped passive option lists onto the user (`Bạn tự làm đi chứ sao đưa cho tôi?`).
3. **Discussion Blindness**: In every active workspace, the user had to explicitly order the agent to inspect discussions (`xem thêm discuss`, `check discussion tiếp để brainstorm`, `Chưa đủ đâu, còn phải brainstorm + đọc thêm discussion`). Agents never proactively mined community discussions during stagnation because:
   - Neither `AGENTS.md` nor `SKILL.md` documented the new `ai-harness discussion` or `ai-harness codabench` CLI commands.
   - The Agent Bridge Context HUD never gave an actionable alert when stagnation occurred.
   - SOP step 10 lacked explicit directives mandating discussion retrieval and forbidding premature freezing while quota remains.

## What changed

- **`AGENTS.md`**:
  - Added **Working Principle 10**: `Anti-Defeatism, Quota Utilization & Proactive Mining`. Explicitly forbids premature freezing or halting submissions while quota/compute remains. Mandates autonomous scientific initiative and proactive discussion mining upon stagnation.
  - Added `ai-harness discussion list/view`, `ai-harness submission list`, and `ai-harness codabench status/download` to Section 3 Essential CLI Commands.
- **`harness/skill_injector.py`**:
  - Added **Rule 3.7**: `Anti-Defeatism, Quota Utilization & Proactive Discussion Mining` in generated `SKILL.md`.
  - Updated **SOP Step 10**: Mandates proactive discussion retrieval (`ai-harness discussion list <comp>`) upon stagnation and reinforces that a plateau never authorizes freeze.
  - Section 5: Formally documents native CLI commands for `discussion list/view`, `submission list`, and `codabench status/download`.
- **`harness/agent_bridge.py`**:
  - In `_research_continuity_hud_lines`: Added an immediate warning `⚠️ STAGNATION / PLATEAU ADVISORY` when `reassess_recommended` is True or consecutive non-improvements $\ge 2$, instructing the agent not to freeze and to run `ai-harness discussion list <comp>`.
- **`harness/research_memory.py`**:
  - In `resume_protocol`: Enriched stagnation advice with explicit guidance to mine discussions and explore orthogonal mechanisms autonomously.
- **Tests**:
  - `tests/test_skill_injector.py`: Added `test_generate_skill_anti_defeatism_and_cli` verifying that generated `SKILL.md` files contain Rule 3.7, anti-freeze mandates, and discussion/codabench commands.
  - `tests/agent_bridge/test_hud_ergonomics.py`: Added `test_stagnation_advisory_in_hud` verifying that the stagnation advisory is rendered into the Context HUD upon plateau.

## Approach

- Embedded the anti-stagnation and proactive exploration rules directly into the three canonical channels that shape agent behavior:
  1. `AGENTS.md` (read as system instructions by Antigravity, Codex, Claude Code).
  2. Dynamic task skills (`.agents/skills/ai-harness/SKILL.md` generated by `harness/skill_injector.py`).
  3. The runtime Context HUD (`ai-harness-agent context`).
- Kept the advice actionable: rather than just saying "don't freeze", the HUD and SOP point directly to `ai-harness discussion list <comp>` as the immediate next step.
